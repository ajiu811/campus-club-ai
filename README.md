# 团团 · 并行设计工作台

> 目标：**同一个空间里同时开几个任务、各做一个界面，风格自动一致，最后能拼成一个完整页面。**
> 风格基准 = 社团广场设计稿（截图）+ `index.html`（v1 参考实现，**只读**）。
> 图片与小细节都做成了可替换的槽位，后面换素材不用重做界面。

---

## 一、这套文档怎么起作用

| 你的诉求 | 靠什么实现 |
|---|---|
| 几个任务同时开工 | 侧边栏「团团」空间分组上点「新建任务」，每个任务自动归入这个空间，各自独立上下文、互不干扰 |
| 风格一致 | 所有任务都读同一份 `DESIGN.md` + 只准引用 `assets/tokens.css` 的变量，禁止写死色值 |
| 最后拼到一起 | `MODULES.md` 约定每个模块的文件名、根节点 id、类名前缀、事件名；前缀隔离 → 不会串样式 |
| 后面换图片 / 改细节 | `assets/media.css` 图片槽位 + `ASSETS.md` 清单，换图只改一行或覆盖一个文件 |
| 改整体风格 | 只改 `assets/tokens.css` 的变量值，刷新即全站生效，模块一个都不用重生成 |
| 挨个检查 | 右侧结果区「网页」页签看预览、「变更」页签看改动；侧边栏状态标记聚合待确认/已完成未读 |

⚠️ **空间本身不保证风格一致**：同一空间只是共享文件目录和任务分组，任务之间上下文是独立的。真正的一致性来自「每个任务都 `@` 引用同一份规范 + 只准用变量」，所以**每段提示词里的 `@` 引用不能删**。

## 二、目录速览

```
团团/
├── README.md          ← 本文件（先看这个）
├── DESIGN.md          ← 设计契约：配色/字体/圆角/组件/红线
├── MODULES.md         ← 并行分工表、命名空间隔离、拼装规则、验收清单
├── TASKS.md           ← 00~07 + 99 号任务的可复制提示词
├── ASSETS.md          ← 图片槽位清单与换图方法
├── style-guide.html   ← 可视化规范页：色板、组件、图片槽位，改完风格刷新验收
├── index.html         ← v1 参考实现，只读
├── assets/
│   ├── tokens.css     ← 设计变量唯一来源（改风格只改这里）
│   ├── base.css       ← 全局基础样式与通用类
│   ├── media.css      ← 图片槽位注册表（换图只改这里）
│   └── img/           ← 占位图；以后放真实图片
├── sections/          ← 并行任务输出区（一任务一 html + 一 css）
├── versions/          ← 拼装前快照
└── app.html           ← 99 号拼装任务的产物（目前还没有）
```

## 三、三步开跑

**第 1 步 · 准备（已完成）**
规范层文件已经建好。可以先打开 `style-guide.html` 看一眼基础风格是否符合预期；不符合就用 `TASKS.md` 的 **00 号规范维护任务**调整。

**第 2 步 · 并行开任务**
在侧边栏「团团」空间分组上点「新建任务」，创建时把「选择工作空间」指向 `团团` 目录。打开 `TASKS.md`，把 **01~07** 号提示词整段复制进各自任务，可同时发起、同时跑。建议：
- 任务标题统一 `团团-03 六大分类`，方便筛选；
- 每个任务开 **Plan 模式**先看方案再动手；
- 一批 3~4 个，验完再开下一批，避免一次开太多拖慢响应。

**第 3 步 · 挨个验收 + 拼装**
- 侧边栏状态标记会聚合显示「待确认 / 已完成未读 / 失败 / 进行中」，点图标直接定位；
- `Ctrl+[` / `Ctrl+]` 在任务间前后切换；需要并排对照用任务右键「在独立窗口中打开」；
- 每个任务看右侧「变更」页签确认只改了自己那两个文件，按 `MODULES.md` 第七节验收清单过一遍；
- 全部通过后，开 **99 号拼装任务**生成 `app.html`，在「网页」页签预览。

## 四、三个常见操作

| 想做什么 | 怎么做 | 要新建会话吗 |
|---|---|---|
| **换整体风格**（主色、圆角、字号…） | 改 `assets/tokens.css` 变量值 → 刷新 `style-guide.html` 验收 → 在 `DESIGN.md` 变更记录留一行 | 不用 |
| **换接入的图片** | 覆盖 `assets/img/` 同名文件，或改 `assets/media.css` 对应一行 `url(...)`；详见 `ASSETS.md` | 不用 |
| **加一个新界面** | 在 `MODULES.md` 分工表登记新前缀和根节点 id → 复制 `TASKS.md` 模板改一改 → 开新任务 → 最后让 99 号重新拼装 | 新任务本身即新会话 |

改结构/组件规格（比如栅格改 3 列、卡片高度变了）→ 改 `base.css` + `DESIGN.md`，再**新建任务**让相关模块按新契约重生成。
若把规范也写进了项目指令或 `.codebuddy/rules`，那些文字改动**必须新建会话**才生效；只改 `tokens.css` / `media.css` 这类数据文件则刷新即生效。

## 五、回退到上一个版本

- **单个任务内**：鼠标悬停到那条消息上点「回退」，确认框会列出受影响产物及处理方式（**特别看清「将被删除」**）；想换个要求重跑用「编辑」，只想重跑最后一轮用「刷新」。注意：这些入口**只对本地任务提供，项目任务/云端任务没有**。
- **整体回退**：消息级回退只管单个任务，多个任务写同一目录时（A 任务回退不会管 B 任务的文件）必须靠版本管理。建议给空间加一层 Git：

```
git init && git add . && git commit -m "团团 v1 基线"
git tag v1-baseline          # 每次改风格/拼装前打一次
```

  回退前先把当前状态 commit 或 stash，别直接丢弃未提交改动。不想用 Git 时，至少把 `sections/` + `assets/` 复制进 `versions/v2/` 再动手（99 号拼装任务已内置这一步）。

## 六、三条铁律

1. **规范层文件只有 00 号任务能改**：`tokens.css` / `base.css` / `media.css` / `DESIGN.md` / `MODULES.md` / `ASSETS.md`。模块任务一律只读。
2. **一任务两文件**：每个模块只写 `sections/xx.html` + `sections/xx.css`，类名前缀独占，绝不碰别人的文件。
3. **不硬编码**：颜色、字号、圆角、阴影、间距、图片路径一律 `var(--xxx)` —— 这是"改一处、处处生效"和"最后能拼起来"的前提。

# 社团一站通（团团）

> **社团一站通** 是产品名，**团团** 是页面右下角那只 AI 助手的名字。

面向高校社团场景的一站式服务原型：**社团发现 + 活动报名 + 个性化推荐 + 分级治理**，右下角接入扣子（Coze）智能体「团团」做问答助手——找社团、看活动、报名、问制度，都在这一个页面里完成，所以叫「一站通」。

整套前端是一个自包含的 `index.html`（约 320 KB），双击即可打开；AI 对话由一个零依赖的 Node 代理转发，访问令牌只存在服务端。

- 前端：原生 HTML / CSS / JavaScript，无框架、无构建步骤
- 后端：Node.js 内置模块，无 npm 依赖
- 智能体：扣子开放平台 Chat v3 API（流式 SSE）

> 这是**交互原型**，不是可直接上线的生产系统。登录、审批、数据落库均为前端模拟，详见 [权限与边界](#权限与边界)。

## 界面速览

| 模块 | 你能做什么 |
|---|---|

| **个性化推荐** | 用星座、MBTI、兴趣标签和浏览/关注/报名记录给活动与社团打分，每张卡显示匹配度与「凭什么推给你」 |
| **个人中心** | 资料编辑（头像本地上传、星座、MBTI）、活动日历、足迹、白杨积分、我的推荐偏好 |

## 快速开始

### 只想看界面（10 秒）

双击 `index.html`。全部页面、推荐算法、交互都能用。

右下角的 AI 抽屉会提示「当前离线」——因为没有后端可以转发请求，这是预期行为。

### 完整跑起来（含 AI，约 2 分钟）

需要 **Node.js 18 或更高**（用到了内置 `fetch`），不需要 `npm install`。

```bash
# 1. 启动代理服务，默认端口 8787
node server/server.js

# 2. 浏览器打开
#    http://localhost:8787
```

服务同时托管静态页面和接口，所以从这里打开不存在跨域问题。

三个演示账号，登录页点一下即填：

| 学号 | 密码 | 身份 | 能看到什么 |
|---|---|---|---|
| `20240001` | `240001` | 普通学生 | 广场、活动、个人中心 |
| `20240002` | `240002` | 社团骨干 | 额外解锁「快捷工作台」 |
| `20240003` | `240003` | 校团委管理员 | 再解锁「治理看板」 |

### 接上真实的团团（需要一个扣子令牌）

1. 在[扣子开放平台](https://www.coze.cn/open/oauth/pats)创建**个人访问令牌**（以 `pat_` 开头）
2. 打开 `http://localhost:8787/setup`，填入 `bot_id` 与令牌，保存
3. 页面顶部会回显账号名与令牌指纹（长度 + SHA1 前 10 位），用于确认写对了
4. 回到首页点右下角悬浮球，发一句话测试

也可以不用 `/setup`，直接写 `server/token.json`：

```json
{ "bot_id": "你的智能体 ID", "pat": "pat_xxxxxxxx" }
```

或者用环境变量覆盖（**部署到公网时推荐这种方式**）：

```bash
COZE_BOT_ID=xxx COZE_PAT=pat_xxx node server/server.js
```

想先调界面、不想连扣子，用演示模式：

```bash
MOCK=1 node server/server.js   # 返回固定文案，不消耗额度
```

## 权限与边界

这一节比功能介绍更重要，决定了这个东西**能拿来做什么、不能拿来做什么**。

### 1. 角色权限（当前为前端模拟）

| 能力 | 普通学生 | 社团骨干 | 校团委管理员 |
|---|---|---|---|
| 社团广场 / 活动报名 / 个人中心 / AI 助手 | 有 | 有 | 有 |
| 快捷工作台（审批活动、管理成员） | 无 | 有，**仅限本人所在社团** | 有，覆盖全校社团 |
| 治理看板（数据监控、安全日志、知识沉淀） | 无 | 无 | 有 |

**重要**：这三档身份目前写在前端（`role` 变量 + localStorage），只控制界面显隐，**不是真实权限**。打开浏览器控制台改一行就能提权。真实部署必须由服务端签发身份，并在数据库层（如 Postgres 的行级安全策略）做校验，前端藏按钮只是体验优化。

### 2. 数据边界

所有用户数据都在**你自己的浏览器**里，没有上传，也不跨设备：

| 存储键 | 内容 |
|---|---|
| `tt_session` | 当前登录学号 |
| `tt_interest_tags` | 兴趣标签，按学号分组 |
| `tt_behavior` | 关注、报名、收藏，按学号分组（推荐引擎的输入） |
| `tt_profile` | 昵称、学院年级、星座、MBTI |
| `tt_avatar` | 头像（压缩后的 base64，几百 KB） |
| `WB_STORE` | 工作台里上传的文件，上限约 2 MB |

推论：换电脑、换浏览器、清缓存，**数据就没了**；两个同学在同一台电脑上登录，各自的数据互不干扰（按学号隔离）；推荐结果不会跨设备同步。

### 3. 密钥边界

- 令牌**只**从 `server/token.json` 或环境变量 `COZE_PAT` 读取，绝不下发到浏览器
- 仓库里的 `.gitignore` 已排除 `server/token.json`，**这个仓库不含任何令牌**
- `/setup` 与 `/api/token` 是本地便利功能，会把令牌写进本机文件；**部署到公网前必须删掉这两个入口**，否则等于开放了一个写令牌的接口
- 前端旧版有一处 `?pat=` 写 localStorage 的调试逻辑，正式使用前应清理

### 4. 平台边界（扣子侧）

这一条经常被问：**别人能不能用他自己的令牌调用你这个智能体？**

个人版不能。扣子官方文档写得很明确：令牌只对**你是空间所有者的工作空间**有效，「如果智能体或知识库等资源位于其他人拥有的工作空间中，你创建的服务访问令牌无法调用这些资源」。别人拿自己的 PAT 加你的 `bot_id`，只会得到 4101（无权限）。

所以让别人用上「团团 + 知识库」，只有三条路：

| 方式 | 对方需要什么 | 说明 |
|---|---|---|
| **你部署服务端代理**（推荐） | 一个网址 | 令牌留在你服务器上代答，对方不需要扣子账号；可加访问口令与每日上限 |
| 发布到扣子商店 | 扣子账号 | 能在扣子 App/网页里对话，知识库对全体用户可见 |
| 对方自建智能体 | 自己的账号与令牌 | 把知识库文档给他一份，各自维护 |

### 5. 原型边界

| 事项 | 现状 |
|---|---|
| 登录 | 输入学号即登录，**没有密码校验**，任何人填同一学号就是同一个人 |
| 审批流 | 点按钮即通过，没有真实流程引擎与通知 |
| 数据持久化 | 存浏览器本地，无多端同步、无服务端备份 |
| 并发与安全 | 无鉴权中间件、无限流、无审计 |

结论：适合课程作业、评奖展示、需求讨论；**不适合**直接承载真实的学生数据和真实审批。

## 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/health` | 健康检查，返回 `{ ok, mock, configured, bot_id }`；前端靠它判断走代理还是离线模式 |
| `POST` | `/api/chat` | 转发对话，SSE 流式。请求体 `{ message, conversation_id? }`，事件为 `{ t: 'd' \| 'sug' \| 'done' \| 'err' }` |
| `GET` | `/setup` | 本机用的令牌配置页（公网部署请删除） |
| `POST` | `/api/token` | 写入 `token.json` 并回显指纹（公网部署请删除） |

前端会依次探测 `''`、`http://localhost:8787`、`http://127.0.0.1:8787` 的 `/api/health`：同源优先，双击打开时回退为离线模式，界面永远不会白屏。

## 常见问题

**双击打开后 AI 用不了？**
`file://` 协议下没有后端，属于预期。跑 `node server/server.js` 后从 `http://localhost:8787` 打开。

**提示「服务端尚未配置令牌」？**
去 `/setup` 填 `bot_id` 和 `pat_` 令牌，或在 `server/token.json` 里写。

**提示 4100 / 4101？**
4100 多为令牌不存在或格式不对（必须以 `pat_` 开头）；4101 是没权限，检查令牌所属工作空间是否包含该智能体。

**回答每次都是同一段话？**
启动时带了 `MOCK=1`，去掉即可。

**改了 `index.html` 但同学那边没变化？**
浏览器缓存。服务端目前未设缓存策略，交付时建议给引用加版本号（`?v=日期`）或配置 `Cache-Control`。

**手机能用吗？**
有响应式适配（`max-width: 640px` 断点），但信息密度按桌面端设计，手机上体验一般。
